# Factor Flight

Single-file canvas game: all HTML, CSS and JS are in `index.html`. No build step. Hosted on GitHub Pages.

## Working with Ken
- Ken is not a terminal user. Prefer GUI-friendly steps (GitHub web upload and web editor).
- No em dashes in any writing for Ken (README, commits, UI copy, replies). Keep answers short.

## Structure (one IIFE in index.html)
- `CFG` at the top: `MIN`/`MAX` times tables (2 to 12), `ROUNDS` facts per mission, `SHIELDS`, `HISTORY`, `LANES`.
- Perspective: `project(wx, u)` with `f = u^1.5`. Objects (star, planet, comet) fly from a vanishing point toward the ship.
- Rounds: `newRound()` builds `{kind, product, a, b, ...}` with kind 'factors', 'product' (a x b, catch the product) or 'missing' (a x ? = p). No kind three times in a row. `onCapture` handles scoring and `badHit` costs a shield.
- Controls: bottom bar (`#controls`) with a slider and arrow buttons so a thumb does not cover the ship, plus arrow keys. `shipY` sits above the bar.
- Music: a generated 4-bar loop (A minor, 112 BPM, drums, bass, lead, pad) from `defaultSong()`, played by the WebAudio `music` engine with a lookahead scheduler. Hooks: `music.start()` in `startGame`, `music.stop()` on lose and win, `music.duck()` on a bad hit, `music.setFactor()` speeds the tempo up as rounds are won. The mute button calls `music.applyGain()`. Songs live in `SONGS` (`defaultSong` is Star Loop, the free one); `useSong(id)` switches the live `song`, and `startGame` loads the player's choice.
- Players: the start screen (`showStart`) lists `players()`, the names saved in `db` in the order they were added, plus a New pilot button (`showNewPlayer`). With no players (a fresh device) it opens straight to the new pilot form. Names are checked by `nameProblem` (1 to `NAME_MAX` (16) letters, numbers, spaces, ' . and -, no duplicates ignoring case), so they are safe in HTML as they are; `rec` uses an own-property check so names like "constructor" work. A save from before (no `RKEY` 'factor-flight-roster' flag) gets the four `LEGACY` players (Mason, Macauley, Mom, Dad) added once so nothing disappears. The keydown handler leaves keys alone while an input has focus. Picking a name opens `showProfile`: coin balance (number only) with an "i" button that toggles the how-to-earn note (`#coinhelp`), a Rewards button with a red dot when `rewardsNews(r)` (daily pay waiting, or `canBuy(r)` something in the Hangar), Start mission button, speedrun picker (one button per table) and the progress grid. Start mission and the speedrun buttons open `showLaunch(name, n)`: the speed picker (with `PACES[k].about` below it), the mission's focus facts or the speedrun's best time, and a Launch button, with Back to the profile. Menus are HTML built by `showPanel(html, acts, opts)`; buttons with `data-act` call `acts[name]`. `opts.back = { label, on }` adds the Back button that floats in the top left (`.backbtn`, also Escape); the profile uses it as Players, the Rewards page as Back.
- Stats live in localStorage under `factor-flight-players`, per player: `games`, `wins`, `best` (missions), `coins`, `coinsEarned`, `daily`, `pace`, `shipLevel`, `shipColor`, `song`, `owned`, `collection` (reward id to count), `sold`, `boosts`, `speed[n]` (best speedrun time per table) and per fact (`"3x7"`, smaller first) `h`, the last `CFG.HISTORY` (10) answers as '1'/'0'. Older answers are dropped. `logFact` is called from `onCapture` and `onLane`. `factLevel` grades a fact from `h`. Data is per device and browser.
- Modes (`mode`): 'mission' plays `plan` from `planMission` (up to 8 shaky facts, then new ones, then known ones as review), with shields. 'speed' drills table `speedN`: each question is one row of answers across `CFG.LANES` lanes (`spawnWave`), the question rides on a gate (`drawGate`), and the lane the ship is in when the row arrives is the answer (`resolveWave`). No shields; a missed question goes back in `queue`. The ship snaps to lanes in speed mode.
- Coins: `COINS` sets the payouts and `REASONS` their labels. `payAnswer` pays each right answer (tricky facts more than known ones, a bonus for first try and for a fact turning green), using levels from the start of the game so missing on purpose never pays. Finishing bonuses are added in `win`. `perfectPrize` runs last in `win` for a game with no wrong answers: on Slowish it adds `earned.double` (the game's coins again), on Medium or Fast it adds one odds boost (`r.boosts`). `bankCoins` moves the game's `earned` coins into the player's `coins` (and lifetime `coinsEarned`) and returns the breakdown HTML for the end screen; a lost mission keeps what it earned. For the rewards screen: `wallet.balance(name)`, `wallet.spend(name, n)` (returns false if short) and `wallet.add(name, n)`, also on `window.FactorFlight`.
- Rewards (gacha): `REWARDS` holds `price`, `tiers` (chance, color token, label; chances add up to 1) and `items` (`id`, `name`, `tier`, `src` like `rewards/common/green-slime.svg` with no leading slash, and a `color` for the fallback). `openLootBox` is Ken's roll logic. Creature art is one SVG per item in `rewards/<tier>/`, drawn by `tools/make-reward-art.py` (shared cartoon style: navy outline, gradient fill, shiny eyes); locked items show the art as a faint silhouette. Items without `src` fall back to `creatureSvg`. `showRewards(name, tab)` is the Rewards page: the slim daily pay bar (`dailyBar`) on top, then tabs Collection (`collectionHtml`; found creatures open large in `#viewer` via `viewItem`) and Hangar (`hangarHtml`, `hangarBuy`); `rewardsTab` remembers the tab. `openReward` spends coins, rolls, saves `collection[id]` counts and plays the box reveal. Extra copies sell from the big view (`sellItem`): each tier has a `sell` value kept below `price` (a random roll sells for about 14, so buying and selling never makes coins), the count is checked at sale time and one copy always stays, and a 400ms lock stops double taps. A `storage` listener reloads `db` and redraws the open menu (`opts.redraw`) when another tab saves, so two tabs can't undo each other. Opening a box uses up one odds boost if the player has any (`boostsOf`) and rolls from `BOOSTED`: Common removed and the other tiers scaled to fill its share (Rare 67%, Epic 30%, Legendary 3%); the Collection tab then shows the boosted odds. `openLootBox` falls back to the database's first tier. Opened from the progress page and from end screens when the player can afford a roll.
- Speed: `PACES` (fast 1, medium 0.8, slow 0.5) divides `travelTime`, and spawn spacing follows it. Each player's choice is saved as `pace` and picked on the launch dialog; `pace` is set in `startGame`. Fast adds `COINS.fastBonus` (20%) of the game's coins in `bankCoins`. `spotX` places each mission number at the spot farthest from numbers arriving around the same time, and keeps edges open so a player can park there to skip and think: Slowish never sends anything to either edge, Medium never has both edges covered at once (`edgeOf`), Fast has no rule. The edge zone is the catch reach (`catchDist`, with sensors) from `LIM`. In a speedrun Fast has 4 answers in 4 lanes, Medium 3 answers in 4 lanes (open edge lane on a random side), Slowish 3 answers in the middle of 5 lanes (`lanes`, `laneSpan`, set in `startGame`; each wave stores `first` and `n`). Flying an open lane calls `onSkip`: nothing logged or paid, the question goes back in `queue`.
- Quit: the red X (`#quit`) or Escape calls `askQuit`, which sets `paused` (the frame loop skips `update`) and shows `#confirm`. `gameSeconds()` leaves out paused and frozen time. Quitting banks the coins earned so far and opens the profile.
- Hangar (the Hangar tab of the Rewards page): spend coins on ship upgrades, songs and power-ups. Ships are 4 levels in `SHIPS` (look plus perk): level 2 has 4 shields, level 3 has 5 and unlocks `PAINTS`, level 4 adds sensors (`SENSOR` scales the catch zone up for right answers and down for wrong ones, using `wanted(o)`). The looks are placeholders until Ken's designs; `paintShip(g, style, size, flicker)` draws any style and `shipPic` makes Hangar pictures. Saved per player as `shipLevel`, `shipColor`, `song` and `owned` (song and power-up ids).
- Power-ups (`POWERS`): Boost (world at 2x for `BOOST_SECS`), Zap (removes the nearest wrong number, or one wrong lane in a speedrun) and Freeze (world and timer stop for `FREEZE_SECS`; the ship can still steer). Bought and upgraded in the Hangar (`prices` per level, 3 levels; level saved as a number in `owned[id]`, old `true` reads as 1 via `powerLv`). Owned ones fly in as pickups (`spawnPickup`, drawn by `drawPickup`) and are used by flying into them (`usePower`). `tickPowers` runs timers in real time that stop during Freeze: each power waits about `POWER_EVERY[level]` seconds, only one pickup is out at a time, and the next waits `POWER_GAP` (3) seconds after one is gone. Missions place pickups with `spotX`; a speedrun sends one with a row in a random lane at 1.8x speed so it arrives first. `update` uses `wdt` (world time) for spawning and movement.
- Daily pay: collected from the bar at the top of the Rewards page (`dailyBar`, `claimDaily`). `payDay()` is a day number that ticks over at 3am Eastern (`DAILY`, via Intl so daylight saving is handled). `dailyAmount(streak)`: days 1 to 3 of each week pay 10, days 4 to 6 pay 25, day 7 pays 100 times the week number. Saved per player as `daily: { day, streak, pweek, pauses }`. Missed days use pauses (`dailyState`): the first each streak week is free and applied on Collect, a second costs `DAILY.pauseCost` (100) via `keepStreak` or the player can Start over; a gap over `DAILY.maxGap` (2 days) or a third pause in a week breaks the streak.
